# Kenya Valuers Project Instructions

## Purpose

Build a premium-property discovery and professional-services platform for Kenya Valuers & Estate Agents. The first release must improve qualified property and service leads. It must not operate as an open marketplace or issue a valuation.

## Current state

Discovery and product requirements are prepared. No application stack, client-system access, third-party vendor, production environment or data migration has been approved.

## Entry points

- `PRD.md`: approved-for-discussion product direction and Phase-0 requirements.
- `.claude/plans/kenya-valuers-init.md`: Sprint 0 plan.
- `.claude/CLAUDE.md`: local commands and integration placeholders.
- `MEMORY.md`: durable operational notes.

## Working conventions

- Treat all client inventory, leads, valuation instructions, analytics and documents as confidential.
- Keep formal valuation work separate from automated property discovery or lead forms.
- Do not invent listing facts, professional credentials, prices, locations, response commitments or KPI baselines.
- Prefer small, tested changes. Obtain client approval before selecting paid vendors or integrating client data.
- Use `scripts/lint-content.sh` for project-authored Markdown and JSON.

## Portfolio handoff contract

JayOps provides the source decision and active action queue. Completion requires source evidence, destination repository, delivery reference, verification evidence, JayOps updates and a follow-up owner. See `/home/jay/dev/JayOps/ops/portfolio-automation.md`.

Jay must explicitly approve client contact, client-data access, credentials, external services, production changes, migrations, publication, payment or deployment.
